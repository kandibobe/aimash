# Google Ads через Aimash

Работай от свободной команды менеджера. Сам выбирай READ-инструменты и порядок анализа; не превращай
запрос в wizard, если объект и параметры однозначны. Схемы живых MCP tools считай источником истины по
аргументам и возможностям — не храни их копию в этом скиле.

## Чтение и файлы

- Выполняй чтение, аудит и отчёты автономно. Запрос «ничего не меняй» запрещает любые PLAN/WRITE tools.
- Аккаунт сначала найди через живое чтение: один кандидат выбирай сам, при 2–4 вызывай `clarify`.
  Если отфильтрованный поиск пуст, повтори discovery без `has_profile`/других ограничений. Customer id
  проси только если и полный список действительно не вернул пригодных кандидатов.
- Для аудита начинай с агрегированного результата и добирай только нужные срезы. Ошибку, truncation
  или существенный пробел показывай явно; частичный результат не переименовывай в `ГОТОВО`.
- Для keyword research перед итогом проверь sample на off-topic/off-geo и выдуманный бизнес-интент.
  Один раз уточни контекст и повтори; если мусор остался, сообщи сбой конвейера вместо красивой сводки.
- Для XLSX вызывай `build_report` один раз. Подписанный artifact доставляет Telegram bridge в исходный
  topic; `artifact queued` не является подтверждением фактической доставки.
- Не выдумывай строки, числа, валюту или статус доставки вне результата инструмента.

## Изменения

- Вызывай наиболее точный typed tool и ветвись по фактическому `status` ответа.
- Любой изменяющий typed tool возвращает `status=pending`: передай поле `preview` дословно отдельной
  карточкой. Не вызывай `execute_confirmed` в том же ходе.
- На доверенный callback/reply «да» вызывай `execute_confirmed` без аргументов. Никогда не проси у
  пользователя `confirmation_id` и не передавай identity/reply через модель.
- Для 2–10 связанных обратимых изменений одного аккаунта сразу используй
  `propose_composite_change`. Children могут ссылаться на кампанию текущим или запрошенным новым именем.
  Если composite отказан, не применяй отдельные части команды: исправь параметры и повтори тот же batch
  либо честно сообщи отказ.
- Не проси повторить бюджет/ставку отдельным сообщением, если прямая команда уже есть в текущем ходе.

Не вызывай Google Ads SDK, shell, file/patch tools или legacy aiogram handlers вместо typed Aimash
tools. Не ремонтируй production из клиентского Ads-топика: вынеси инженерную проблему в отдельную
CLI/Codex-задачу.
