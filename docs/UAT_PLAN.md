# План ручного приёмочного тестирования (UAT) — Aimash

> **[legacy-референс]** Этот план принимает развёрнутый aiogram-бот. Его бизнес-сценарии и ожидаемые результаты
> остаются референсом, но кнопочные шаги **не доказывают готовность Hermes**. Целевая приёмка — [`SPEC.md` §13](../SPEC.md) и
> [`HERMES_SPEC.md` §12](../deploy/hermes/HERMES_SPEC.md); точка входа — [`TZ-Aimash-Hermes-Agent.md`](TZ-Aimash-Hermes-Agent.md).

Версия 1.0 · для владельца проекта. Ты прогоняешь сценарии в Telegram, отмечаешь **OK / FAIL**,
собираешь скриншоты и присылаешь список FAIL — разработчик по ним чинит.

**Все формулировки кнопок/команд — реальные (из кода).** Мутации возможны ТОЛЬКО на тест-аккаунте
**Aimash Draft `7753643025`**. Чтение — по дочерним MCC. Пользовательский гайд — [USER_GUIDE.md](USER_GUIDE.md).

## 0. Подготовка окружения (один раз, ~15 мин)

- [ ] **.env**: `TELEGRAM_WHITELIST_CHAT_IDS` содержит твой chat_id; `GOOGLE_ADS_ALLOWED_CUSTOMER_IDS=7753643025`;
      `GOOGLE_ADS_LOGIN_CUSTOMER_ID` = ID тест-MCC; `OPENROUTER_API_KEY`, `GOOGLE_ADS_*` заполнены.
      Для `/sheets` и генерации ключей нужен OAuth-scope `drive.file` / `spreadsheets.readonly` (см. [DEPLOYMENT.md](DEPLOYMENT.md), [OAUTH_SETUP.md](OAUTH_SETUP.md)).
- [ ] **Бот запущен ровно в одном экземпляре**: `python -m bot.main` (или на VPS `docker compose up -d`).
      Если бот молчит — в консоли ищи `409 Conflict` (работает второй инстанс → убей дубль).
- [ ] **Тест-аккаунт**: на Draft есть **минимум 2 кампании** — одна ENABLED, одна PAUSED.
- [ ] **Google Ads UI** открыт на Draft во втором окне — для сверки «ничего не изменилось».
- [ ] **Второй Telegram-аккаунт НЕ из whitelist** (для теста fail-closed, Сессия 7) — опционально.
- [ ] Доступ к **консоли/логам бота** (`docker compose logs -f bot` или окно процесса).
- [ ] `/balance` показывает ненулевой баланс OpenRouter; `/quota` < 50%.

**Где брать данные для баг-репорта:** консоль бота (traceback, секреты уже отредактированы);
`/diag` (последние ошибки по коду `XXXX` из сообщения «что-то пошло не так»); `/journal` (аудит действий).

## Правила сбора артефактов

- **Скриншоты:** имя `s<сессия>-<шаг>.png` (напр. `s2a-04.png`). 📸 в шаге = скрин обязателен даже при OK.
- **Формат баг-репорта** (один блок на ошибку):
```
[FAIL] Сессия 2A, шаг 2A.4
Время: 2026-07-05 14:32 (укажи TZ)
Ввод (дословно): «повысь бюджет Search Test на 20%»
Ожидалось: черновик «было → станет» с кнопками ✅/❌
Получено: «⚠️ Что-то пошло не так … (код 3f2a…)»
Скрин: s2a-04.png
Лог: фрагмент консоли вокруг времени + вывод /diag по коду
Повторяемость: да/нет
```
- После сессии: список FAIL + отдельно «UX-замечания» (что было непонятно — тоже ценно).
