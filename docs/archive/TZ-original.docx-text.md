# ТЗ-1 — Основное ТЗ, разделы 1–18

*Источник: `Aimash_Technical_Specification.docx`*

#### Aimash
#### Техническое задание
ИИ-агент для управления Google Ads через Telegram
Платформа реализации агента: Hermes (или аналогичная LLM с function calling)
Версия 1.0
## 1. Общее описание
Разработать ИИ-агента для управления рекламными аккаунтами Google Ads. Агент работает на уровне менеджерского аккаунта (MCC) и управляет рекламными кампаниями подключённых клиентских аккаунтов. Всё взаимодействие с агентом осуществляется через Telegram-бот: приём команд, вывод отчётов и статистики, запрос подтверждений.
Ключевой принцип: агент является исполнителем, а не автономным оптимизатором. Агент никогда не принимает решений и не выполняет изменений самостоятельно — он действует строго по командам пользователя. Перед применением любого изменения агент показывает, что именно будет изменено, и ждёт подтверждения («да»). Агент может предлагать улучшения (например, «хотите, я повышу бюджет?», «предлагаю добавить ключевые слова»), но выполняет их только после прямой команды пользователя.
Агент имеет полный доступ к управлению аккаунтами (кампании, бюджеты, ГЕО, аудитории, ставки, ключевые слова, объявления). Агент также выполняет качественное исследование ключевых слов, генерирует рекламные тексты, формирует статистику по каждому подключённому аккаунту, создаёт глубокие отчёты по отдельному аккаунту за произвольный период с выгрузкой в Google Sheets или .xlsx, и создаёт рекламные кампании (в т. ч. GDN и UAC) из загруженных фото и видео.
#### Ключевые возможности
- Полное управление кампаниями, группами, объявлениями, ключевыми словами, ГЕО, аудиториями и ставками — строго по командам пользователя.
- Перед любым изменением агент показывает, что именно изменит, и ждёт подтверждения «да».
- Изменение бюджета — агент меняет бюджет по команде пользователя (например, «смени бюджет», «повысь бюджет на 20% / на $50 / на 500 грн»). По собственной инициативе, без команды, агент бюджет не меняет, но может предложить изменение.
- Работа с ключевыми словами: добавление в кампании с выбором типа соответствия и по типу интента; предложение новых слов.
- Создание кампаний (Search, GDN, UAC и др.) из загруженных фото и видео — с показом черновика и ожиданием команды на запуск.
- Keyword research через Google Keyword Planner (Keyword Plan services).
- Статистика по каждому клиентскому аккаунту, подключённому к менеджерскому аккаунту.
- Глубокие отчёты по одному аккаунту за любой период с экспортом в Google Sheets / .xlsx.
- Генерация рекламных текстов с обязательным подтверждением каждого заголовка и каждого описания.
- Проактивные отчёты и алерты по расписанию через Telegram.
## 2. Архитектура системы
Система состоит из следующих компонентов:
- Telegram Bot — интерфейс взаимодействия: приём команд, вывод отчётов, запрос подтверждений, рассылка алертов.
- AI Agent Core (Hermes) — обработка запросов на естественном языке, анализ данных аккаунта, формирование рекомендаций и действий через function calling.
- Google Ads Connector — модуль интеграции с Google Ads API (чтение и запись).
- Reporting & Export Module — формирование отчётов и выгрузка в Google Sheets / .xlsx.
- Confirmation Layer — слой подтверждения критических операций (бюджет, публикация текстов).
- Database — хранение токенов, логов, очереди подтверждений, настроек и кэша.
- Scheduler — периодические задачи: мониторинг, плановые отчёты, алерты, очистка.
Поток данных: Пользователь → Telegram Bot → AI Agent Core → [Confirmation Layer] → Google Ads API / Google Sheets API. Отчёты и запросы подтверждения возвращаются пользователю через Telegram Bot.
## 3. Интеграция с Google Ads API
- Использовать официальный Google Ads API (актуальная версия, на момент составления — v24).
- Аутентификация через OAuth 2.0 с refresh-токеном.
- Developer Token: basic access уже получен. При необходимости больших объёмов запросов — подать заявку на standard access.
- Реализовать обработку rate limits и quota, пагинацию, батчинг запросов.
- Поддержка работы на уровне MCC и обхода иерархии клиентских аккаунтов.
#### Требуемые операции
- Чтение: кампании, группы, ключевые слова, объявления, бюджеты, ГЕО, аудитории, статистика (impressions, clicks, CTR, CPC, conversions, cost, conversion value, CPA, ROAS и др.).
- Управление кампаниями: создание / пауза / возобновление / изменение кампаний, групп, объявлений, статусов.
- Изменение ГЕО: таргетинг по стране, городу и по точкам с радиусом по координатам (geo radius targeting).
- Аудитории: добавление и изменение аудиторий (audience targeting).
- Ключевые слова: добавление / изменение / удаление ключевых слов и негативных ключевых слов, выбор типа соответствия, настройка по интенту.
- Ставки: изменение ставок и стратегий назначения ставок.
- Бюджет: изменение только по прямой команде пользователя (см. раздел 5).
- Полное управление: агент должен поддерживать все основные операции управления аккаунтом, выполняемые строго по командам пользователя с предварительным показом изменений.
## 4. AI Agent Core (Hermes)
Агент — исполнитель команд пользователя, а не автономный оптимизатор. Он не выполняет изменений по собственной инициативе.
- Приём команд на естественном языке (русский / английский), включая команды вида «повысь бюджет кампании X на 20%», «добавь ключевые слова …», «измени ГЕО на …».
- Использование function calling для вызова операций Google Ads и экспорта отчётов.
- Анализ эффективности кампаний и выдача рекомендаций по запросу.
- Агент может предлагать улучшения (например, добавить ключевые слова, изменить бюджет, оптимизировать ставки), но выполняет их только после прямой команды пользователя.
- Перед любым изменяющим действием агент формирует чёткое описание операции, показывает его пользователю и ждёт подтверждения «да».
- Доступ к актуальным данным аккаунта для корректного формирования команд и предложений.
- Защита от «галлюцинаций»: все изменяющие операции логируются и подтверждаются перед выполнением.
## 5. Модель подтверждения изменений
Агент работает по принципу «показать и подтвердить» (show & confirm). Перед выполнением любого изменяющего действия агент показывает в Telegram, что именно будет изменено, и выполняет операцию только после подтверждения пользователя («да»).
#### Общий поток
- Пользователь даёт команду (например, «измени ГЕО на Киев + радиус 10 км», «добавь аудиторию …», «повысь ставку до …»).
- Агент готовит сводку (summary) всех изменений и показывает её с кнопкой ✅ Подтвердить.
- Операция выполняется только после подтверждения.
- Все подтверждения и отклонения логируются в audit log.
#### Сводка изменений (summary) перед подтверждением
После каждой команды на изменение агент формирует единую человекочитаемую сводку всех изменений, которые будут применены. Сводка обязательно показывает старое и новое значение в формате «было → станет». Большие списки (ключевые слова, минус-слова) не выводятся текстом целиком, а прикладываются ссылкой на XLSX-файл. Под сводкой — одна кнопка подтверждения.
Требования к сводке:
- Для простых значений (бюджет, ГЕО, ставки) — формат «текущее → новое».
- Для списков (ключевые слова, минус-слова, аудитории) — количество элементов + ссылка на XLSX со списком; для ключевых слов указывается тип соответствия.
- Если одна команда затрагивает несколько сущностей — все изменения собираются в одну сводку с одной кнопкой подтверждения.
- Кнопка ✅ Подтвердить (и ❌ Отмена) применяет/отменяет весь набор изменений из сводки.
Пример сводки:
#### Бюджет (особое правило)
- Агент не меняет бюджет по собственной инициативе (без команды пользователя).
- Агент может предложить изменение: «Хотите, я изменю бюджет?».
- По команде пользователя агент меняет бюджет сам — команда вида «смени бюджет», «повысь бюджет кампании X на 20%» / «на $50» / «на 500 грн» является основанием для выполнения. Команда может задавать процент, сумму в $, грн или другой валюте.
- Перед применением агент показывает: текущий бюджет → новый бюджет и ждёт «да».
#### Рекламные тексты (особое правило)
- Подтверждение требуется для каждого заголовка и каждого описания по отдельности (см. раздел 10).
#### Создание кампаний (особое правило)
- Агент создаёт черновик кампании из загруженных материалов, показывает его и ждёт команды пользователя на запуск (см. раздел 11).
## 6. Telegram Bot
- Авторизация: работа только с разрешёнными chat_id (whitelist).
- Приём команд на естественном языке и через слэш-команды: /start, /help, /status, /report, /campaigns, /pause, /resume, /account <id>, /keywords, /export.
- Приём загруженных фото и видео для создания кампаний (раздел 11).
- Свободный текст передаётся в AI Agent Core.
- Inline-кнопки для подтверждений и выбора аккаунта/периода.
- Проактивные уведомления: алерты при аномалиях (резкий рост расхода, падение конверсий), плановые отчёты.
- Форматирование ответов (Markdown, таблицы), отправка файлов и ссылок.
## 7. Работа с ключевыми словами и Keyword Research
Агент выполняет полноценное исследование ключевых слов через Keyword Plan services Google Ads API (программный аналог Keyword Planner) и добавляет ключевые слова в кампании по команде пользователя.
#### Keyword Research
- Приём seed-слов или URL сайта/страницы через Telegram.
- Генерация идей ключевых слов с метриками: среднемесячное число запросов, уровень конкуренции (LOW/MEDIUM/HIGH + индекс), диапазон ставок вверху страницы, сезонность.
- Настройка параметров: гео-таргетинг, язык, сеть (Search / Search+Partners), период.
- AI-слой над данными: кластеризация по темам и интенту, фильтрация нерелевантных запросов, выделение приоритетных кластеров.
- Вывод результата в Telegram: структурированная сводка + выгрузка полного списка (CSV / таблица).
#### Добавление ключевых слов в кампании
- Тип соответствия: агент добавляет ключевые слова с выбором типа соответствия (broad / phrase / exact).
- Определение по интенту: агент классифицирует и группирует ключевые слова по типу интента (например, информационный, коммерческий, транзакционный, навигационный).
- Предложение негативных ключевых слов.
- Предложение новых слов: агент может предлагать добавить новые ключевые слова, но добавляет их только по команде пользователя, показав список и тип соответствия и дождавшись «да».
## 8. Мульти-аккаунтная отчётность (MCC)
Агент работает на уровне менеджерского аккаунта и собирает статистику по всем подключённым клиентским аккаунтам.
- Получение списка дочерних аккаунтов и обход иерархии через CustomerService / customer_client.
- Сбор статистики по каждому customer_id через GAQL.
- Метрики по каждому аккаунту: cost, показы, клики, CTR, CPC, conversions, CPA, ROAS, статус активных кампаний.
- Сводный отчёт по всем аккаунтам + детализация по каждому (по запросу или кнопкой).
- Плановая рассылка (ежедневно / еженедельно) через Scheduler.
- Алерты на уровне отдельных аккаунтов.
- Нормализация валют и часовых поясов в сводном отчёте.
## 9. Глубокие отчёты по одному аккаунту (Google Sheets / xlsx)
Агент формирует детальный многомерный отчёт по одному выбранному клиентскому аккаунту за произвольный период.
#### Выбор периода
- Конкретный день, произвольный диапазон (start/end) или пресет (последние 7 / 30 / 90 дней, month-to-date).
- Данные тянутся через GAQL с фильтром по полю segments.date (оператор BETWEEN). См. документацию GAQL.
#### Содержание отчёта
- Итоги по аккаунту + разбивки: по кампаниям, группам объявлений, ключевым словам, объявлениям, устройствам, сети, по дням.
- Метрики: impressions, clicks, CTR, средний CPC, cost, conversions, conversion value, CPA, ROAS.
- Сравнение период к периоду (где применимо).
#### Форматы выгрузки (на выбор пользователя)
- Google Sheets — агент создаёт новую таблицу через Google Sheets API, пишет каждую разбивку в отдельную вкладку, форматирует заголовки и возвращает ссылку в Telegram.
- .xlsx — агент генерирует Excel-книгу (одна вкладка на разбивку) и отправляет файл вложением в Telegram.
- Отчёты — read-only, аккаунт не изменяется. Доступны по запросу или по расписанию.
Примечание: экспорт в Google Sheets требует дополнительных OAuth-scopes (spreadsheets или drive.file) помимо scope Google Ads API.
## 10. Генерация рекламных текстов
Агент с помощью LLM создаёт качественные рекламные тексты (заголовки и описания) и обязательно отправляет их на подтверждение пользователю перед применением.
#### Требования к генерации
- Генерация headlines и descriptions для Search-кампаний (формат Responsive Search Ads).
- Строгое соблюдение лимитов: headline — до 30 символов, description — до 90 символов, display path — до 15 символов на сегмент. Валидация длины до отправки (учёт кириллицы).
- Контекст: тематика, целевые ключевые слова, УТП, тон, гео, язык.
- Несколько вариантов (например, 10–15 заголовков, 3–4 описания на RSA).
- Учёт best practices: ключевые слова, CTA, уникальность, отсутствие запрещённых элементов (CAPS LOCK, лишняя пунктуация, спам-символы) для прохождения модерации.
#### Confirmation flow для текстов
- Подтверждение каждого заголовка и каждого описания по отдельности. Пользователь подтверждает или отклоняет каждый элемент индивидуально, а не весь набор целиком.
- По каждому элементу агент показывает текст, его длину (с учётом лимита) и указание кампании/группы.
- Inline-кнопки по каждому элементу: ✅ Применить / ✏️ Доработать / ❌ Отклонить.
- При «Доработать» пользователь даёт правки в чат, агент регенерирует конкретный элемент.
- В объявление добавляются только подтверждённые заголовки и описания. Все тексты логируются.
## 11. Создание кампаний из загруженных фото и видео
Агент создаёт рекламные кампании на основе загруженных пользователем материалов. Пользователь загружает фотографии и/или видео, и система автоматически формирует кампании под них.
#### Поддерживаемые типы кампаний
- Google Display Network (GDN) — графические объявления на основе загруженных изображений.
- Universal App Campaigns / App campaigns (UAC) — на основе изображений и видео.
- Другие типы кампаний, использующие медиа (например, Demand Gen, Video) — по мере необходимости.
#### Процесс
- Пользователь загружает фото и/или видео через Telegram (или указывает источник материалов).
- Загрузка ассетов: система загружает изображения и видео в аккаунт как media assets через Google Ads API.
- Система автоматически формирует структуру кампании, группы и объявления на основе загруженных материалов и заданных параметров (ГЕО, бюджет, цель).
- Черновик и подтверждение: агент показывает черновик кампании (структура, ассеты, настройки) и ждёт команды пользователя на запуск. Без команды кампания не запускается.

## 19.1 Общее описание флоу
Данный раздел описывает пошаговый сценарий создания рекламной кампании типа Google Search (Responsive Search Ads) через Telegram-бот. Флоу запускается кнопкой «Создание кампании» и ведёт менеджера через все этапы: выбор аккаунта клиента, описание кампании на естественном языке, автоматическое заполнение настроек, ключевые слова, создание объявления (заголовки, описания, display path), изображения и ассеты, финальная проверка и запуск.
Флоу полностью подчиняется ключевому принципу основного ТЗ: агент — исполнитель, а не автономный оптимизатор. На каждом этапе агент показывает, что именно будет создано/изменено («показать и подтвердить»), и переходит дальше только после подтверждения менеджера. Кампания создаётся в статусе PAUSED (черновик) и запускается только по отдельной прямой команде.

## 19.2 Этап 0. Запуск и выбор аккаунта

- Менеджер выбирает аккаунт клиента. Выбранный customer_id фиксируется как контекст всей сессии создания кампании.
- Агент задаёт открытый вопрос: «Опишите рекламную кампанию».

> 🤖 Бот Аккаунт выбран: Kasi Motors (123-456-7890). Опишите рекламную кампанию — одним сообщением: что продвигаем, на какую страну/город, бюджет, цель. Я сам разложу это на настройки.

## 19.4 Этап 2. Ключевые слова

| Шаг 2 | Ключевые слова |
|---|---|

После подтверждения настроек кампании агент переходит к ключевым словам. Логика этапа развилочная: если менеджер передал ключевые слова — система использует их; если не передал и нажал «Генерация ключевых слов» — система запускает автоматический подбор через Keyword Planner с последующей ручной верификацией в Google Sheets.

| Условие | Поведение системы |
|---|---|

| Слов нет → нажата «🔎 Генерация ключевых слов» | Запускается процесс автоматического подбора и ручной верификации (см. 19.4.2). |

### 19.4.1 Ввод A. Менеджер передаёт ключевые слова
Если менеджер сразу передаёт ключевые слова, доступны четыре способа ввода, плюс возможность задать тип соответствия инструкцией.

| Способ ввода | Как работает |
|---|---|
| Загрузка файла XLSX / CSV | Менеджер прикрепляет файл; агент парсит колонку с ключами (и при наличии — колонку с типом соответствия). |
| Ссылка на Google Sheets | Менеджер вставляет  ссылку на Google-таблицу ; агент читает её через Google Sheets API и берёт ключи из колонки (и тип соответствия, если задан). Таблица должна быть доступна агенту. |
| Вставка текстом | Список ключей сообщением в чат (по одному в строке или через запятую). |
| Инструкция + список | Текстовая команда о типе соответствия + ключи, например:  «используй фразовое соответствие (Phrase Match) для всего списка»  и далее список / файл / ссылка на Google Sheets. |

#### Типы соответствия (match type)
Агент поддерживает все типы соответствия Google Ads: Broad Match (широкое), Phrase Match (фразовое — в кавычках), Exact Match (точное — в квадратных скобках). По умолчанию используется Phrase, если менеджер не указал иное. Тип можно задать на весь список одной инструкцией или поколоночно в XLSX.
### 19.4.2 Ввод B. Генерация ключевых слов («🔎 Генерация ключевых слов»)
Если ключевых слов нет и менеджер нажал «Генерация ключевых слов», система выполняет следующий конвейер:
- Авто-генерация seed-слов. Система автоматически генерирует 10 самых релевантных ключевых слов по теме рекламной кампании и информации о клиенте (LLM на основе описания кампании, URL и профиля клиента).
- Discover new keywords. Система передаёт эти 10 ключевых слов в «Discover new keywords» (Keyword Planner — программно через KeywordPlanIdeaService.GenerateKeywordIdeas, seed = 10 ключей + URL, с учётом ГЕО и языка кампании) и получает расширенный список идей в формате .CSV с историческими метриками (объём запросов, конкуренция, ставки).
- Фильтрация по релевантности. Система отсеивает ключевые слова, нерелевантные бизнесу клиента (AI-слой релевантности на основе профиля клиента и тематики кампании), помечая каждое слово как релевантное / нерелевантное.
- Выгрузка в Google Sheets. Результат отдаётся в формате Google Sheets: таблица со всеми найденными ключами, метриками и пометкой релевантности. Ссылка на таблицу отправляется менеджеру в Telegram.
- Ручная верификация менеджером. Менеджер открывает таблицу, видит, какие ключи помечены релевантными/нерелевантными, и вручную верифицирует финальный список — оставляет нужные ключи и удаляет ненужные строки прямо в Google Sheets.
- Возврат ссылки системе. Менеджер отправляет системе ссылку на отредактированную Google-таблицу. Система берёт верифицированный пользователем список из таблицы и использует ключевые слова только оттуда.

## 19.5 Этап 3. Создание рекламного объявления (RSA)

| Шаг 3 | Объявление: URL, display path, заголовки, описания |
|---|---|

### 19.5.1 URL и Display Path
- Агент спрашивает: «Какой URL рекламируем?» — менеджер вставляет Final URL.
- Агент автоматически формирует Display Path (2 сегмента, релевантные странице и кампании). Display path указывается на этапе создания объявления и не обязан совпадать с реальной структурой URL.
- Агент кратко парсит содержимое посадочной страницы (тематика, УТП, ключевые офферы) — это используется далее для генерации заголовков и описаний.

> Display Path — лимиты Google Ads (актуально на 2026) 2 сегмента, по 15 символов каждый. Пример для авто-дилера в Кении: domain.co.ke/Used-Cars/Nairobi. Для кириллицы и двухбайтовых языков символ считается как 2 — длина валидируется до отправки.

### 19.5.2 Генерация 15 заголовков (headlines)
Агент автоматически генерирует 15 заголовков, используя: (1) ключевые слова кампании, (2) содержимое посадочной страницы (URL), (3) общую информацию о бизнесе клиента. Соблюдаются текущие лимиты Google Ads.

| Элемент | Лимит (2026) | Кол-во |
|---|---|---|
| Headline (заголовок) | до 30 символов | до 15 |
| Description (описание) | до 90 символов | до 4 |
| Display path (сегмент) | до 15 символов | 2 сегмента |
| Final URL | до 2048 символов | 1 |

#### Правки и регенерация
На этапе заголовков менеджер может: заменить заголовки полностью, либо дать правки (например, «сделай 3 заголовка с упором на рассрочку», «убери CAPS», «добавь гарантию»). После правок система выдаёт новый результат — обновлённые 15 заголовков на утверждение. Цикл повторяется до подтверждения.
В соответствии с разделом 10 основного ТЗ подтверждение возможно поэлементно (✅ Применить / ✏️ Доработать / ❌ Отклонить по каждому заголовку), с проверкой длины каждого элемента и учётом best practices (наличие ключа, CTA, уникальность, без CAPS LOCK и спам-символов для прохождения модерации).

> 🤖 Бот 15 заголовков (длина ≤ 30): 1. Поддержанные авто в Кении (24)   ✅ ✏️ ❌ 2. Проверенные б/у автомобили (26)   ✅ ✏️ ❌ 3. Авто с гарантией · Найроби (25)   ✅ ✏️ ❌ … ещё 12 заголовков  ✏️ Доработать всё  \|  🔁 Сгенерировать заново  \|  ✅ Утвердить набор

### 19.5.3 Создание 4 описаний (descriptions)
После утверждения 15 заголовков система переходит к созданию 4 описаний (до 90 символов каждое). Логика идентична заголовкам: авто-генерация на основе ключей, URL и бизнеса; возможность полной замены или правок; поэлементное подтверждение (✅ / ✏️ / ❌) и регенерация по правкам. В объявление добавляются только подтверждённые заголовки и описания.
## 19.6 Этап 4. Изображения объявления (image assets)

| Шаг 4 | Изображения (если применимо) |
|---|---|

После описаний агент предлагает прикрепить изображения к объявлению (image assets), если это возможно для данной кампании/аккаунта.

> Уточнение по доступности (требует подтверждения на этапе внедрения) Image assets в Search показываются не всегда: возможность зависит от соответствия требованиям и статусу аккаунта (история, отсутствие нарушений политик). Технические требования: форматы 1:1 (квадрат) и 1.91:1 (ландшафт), минимум 300×300 px, до 5120 КБ. Текст/логотип, «вшитый» в изображение, не рекомендуется. Если image assets недоступны для аккаунта — этап автоматически пропускается с уведомлением менеджеру. Кнопки: 📎 Прикрепить изображения / ⏭ Пропустить.

### 19.7.2 Автогенерация ассетов под клиента
Для каждого типа ассета агент на базе знаний о клиенте и его сайте предлагает готовое наполнение, релевантное кампании и URL. Менеджер подтверждает или правит.
#### Пример: Доп. ссылки (Sitelinks)
Если менеджер выбирает создать sitelinks, агент автоматически предлагает 6 ссылок на главные и наиболее релевантные кампании страницы сайта (например: Каталог авто, Поддержанные авто, Рассрочка, Trade-in, Гарантия, Контакты) — с заголовком и описанием для каждой.
#### Пример: Структурированные описания (Structured snippets)
Агент предлагает structured snippets, релевантные данной кампании, URL и клиенту: подбирает подходящий заголовок из списка Google (например, «Модели» / «Типы») и набор значений (Sedan, SUV, Hatchback, Pickup …).
Пример: Уточнения (Callouts), Телефон (Call) и т. д.
Аналогично для каждого типа: для callouts — «Гарантия 12 мес», «Trade-in», «Авто с пробегом по РФ/ЕС»; для телефона — подстановка контактного номера клиента; и так далее для всех выбранных типов ассетов.

> Источники данных для автогенерации ассетов • Контент сайта клиента (карта страниц, заголовки, офферы) — для sitelinks и snippets. • Профиль клиента в системе (телефон, адрес, бренд, акции) — для call, location, promotion, business name/logo. • Ключевые слова и тематика кампании — для релевантности callouts и snippets конкретной кампании.

| Шаг 6 | Ad URL options (опционально) |

| Шаг 7 | Финальная сводка объявления и правки командой |
|---|---|

В конце агент выводит финальную сводку объявления и набора ассетов, которые будут использованы. Менеджер может дать команду на редактирование в свободной форме, например:

> 👤 Менеджер «Смени asset → номер телефона с +38012831881 на +38128381238 и смени структурное описание “Топовый автодилер” на “Лучший автодилер”»

> Финальная сводка содержит • Кампанию и настройки (ГЕО, бюджет, стратегия, тип соответствия ключей). • Объявление: Final URL, display path, утверждённые заголовки и описания (с длинами). • Изображения (если добавлены) и полный набор ассетов (текущие + новые). • Ad URL options (tracking, suffix, custom parameters), если заданы. • Кнопки: ✏️ Редактировать командой  /  ✅ Создать черновик  /  🚀 Запустить кампанию.

> Создание и запуск По кнопке «Создать черновик» агент через Google Ads API создаёт кампанию, группу, RSA-объявление, ключевые слова и ассеты в статусе PAUSED. Кампания переводится в ENABLED только по отдельной прямой команде «Запустить» — в полном соответствии с моделью «показать и подтвердить» (разделы 5 и 11 основного ТЗ). Все действия фиксируются в audit log.

*Источник: `Информация о клиентах_1.docx`*

#### Aimash
#### Техническое задание — дополнение
Раздел 20. Информация о клиентах (база знаний клиента) и краулинг сайта
Версия 1.0 · дополняет разделы 6, 7, 10, 11 и 19 основного ТЗ
## 20.1 Общее описание
Раздел описывает новый пункт меню Telegram-бота — «Информация про клиентов». Это персональная база знаний по каждому клиенту, привязанная к конкретному рекламному аккаунту (customer_id) внутри MCC. Менеджер отправляет боту обычным текстом всю актуальную информацию о клиенте (сайт, соцсети, описание бизнеса, услуги, цены, телефоны), а бот сохраняет её в память и использует во всех генеративных задачах: заголовки, описания, ассеты, structured snippets, sitelinks и т. д.
Дополнительно бот краулит сайт клиента: при получении ссылки агент обходит сайт, собирает основные страницы и ссылки, извлекает услуги, цены (если указаны на сайте) и контакты, и формирует структурированный профиль клиента. Этот профиль становится контекстом для релевантной генерации рекламных материалов. Менеджер может в любой момент обновить информацию или запустить повторный краулинг (например, если сайт клиента изменился).
Раздел подчиняется ключевому принципу основного ТЗ: агент — исполнитель, а не автономный оптимизатор. Сбор и хранение информации о клиенте не изменяют рекламный аккаунт. Профиль клиента используется только как источник контекста; любые изменения в Google Ads по-прежнему требуют отдельной команды и подтверждения «да».
#### Зачем это нужно
- Релевантность. Бот понимает, чем занимается клиент, какие у него услуги и цены, и пишет объявления точнее.
- Скорость. В флоу создания кампании (раздел 19) поля заполняются из профиля клиента, а не вручную.
- Единый источник правды. Данные о клиенте хранятся в одном месте и переиспользуются во всех кампаниях аккаунта.
- Актуальность. Кнопка «Обновить инфу» и повторный краулинг держат профиль в синхроне с реальным сайтом клиента.
## 20.2 Пункт меню и кнопки
В главном меню бота добавляется пункт «ℹ️ Информация про клиентов». Внутри пункта работа всегда ведётся в контексте выбранного рекламного аккаунта: за каждым customer_id закрепляется отдельный профиль клиента.

| Кнопка | Действие |
|---|---|
| ℹ️ Информация про клиентов | Открывает раздел. Бот показывает список рекламных аккаунтов MCC (название + customer_id); у аккаунтов с заполненным профилем стоит отметка ✅. |
| 📋 Карточка клиента | Показывает текущий сохранённый профиль выбранного клиента: описание бизнеса, сайт, соцсети, услуги, цены, телефоны, дата последнего краулинга. |
| ➕ Добавить информацию | Бот переходит в режим приёма текста. Менеджер отправляет всю информацию о клиенте одним или несколькими сообщениями; бот разбирает её и записывает в память. |
| ✏️ Обновить инфу | Редактирование существующего профиля: дополнить, заменить отдельные поля (например, новый сайт, новый телефон) или прислать новый текст. Старая версия сохраняется в истории. |
| 🔄 Перекраулить сайт | Повторный обход сайта клиента (полностью или только новые/изменённые страницы). Используется, когда сайт обновился. |

#### Привязка профиля к рекламному аккаунту
Профиль клиента жёстко связан с customer_id рекламного аккаунта. При запуске флоу создания кампании (раздел 19) или генерации текстов (раздел 10) агент автоматически подтягивает профиль того аккаунта, в контексте которого работает. Один аккаунт — один профиль клиента; при необходимости поддерживается несколько брендов в описании, если на одном аккаунте рекламируется несколько направлений.

Если каких-то полей в тексте нет — они остаются пустыми и могут быть дополнены позже либо взяты из краулинга сайта.

## 20.4 Краулинг сайта клиента
При получении ссылки на сайт агент запускает краулинг — обход страниц сайта для сбора структуры и контента. Цель — построить карту сайта, извлечь услуги, цены и контакты, и сохранить структурированный профиль, который далее используется в генерации рекламных материалов.
#### Что собирает краулер

| Сущность | Содержание |
|---|---|
| Карта страниц (sitemap) | Список основных страниц: главная, услуги/товары, о компании, контакты, цены, блог и т. д. — с заголовками и URL. |
| Внутренние ссылки | Ключевые внутренние ссылки для будущих sitelinks (Каталог, Услуги, Контакты, Акции и пр.). |
| Услуги / товары | Перечень услуг и категорий, извлечённых из контента страниц. |
| Цены | Стоимость, если указана на сайте (прайс, карточки товаров, страницы тарифов). |
| Контакты | Телефоны, e-mail, адреса, ссылки на соцсети, найденные на сайте. |
| Офферы / УТП | Ключевые преимущества и предложения (гарантия, доставка, рассрочка и т. п.) — для callouts и заголовков. |
| Мета-данные | Title и description страниц, заголовки H1–H3 — как сигнал тематики. |

#### Процесс краулинга
- Получение URL. Менеджер прислал сайт (в тексте профиля) или нажал «Краулить сайт».
- Обход страниц. Краулер обходит сайт начиная с главной, следуя по внутренним ссылкам и/или sitemap.xml, в пределах одного домена. Учитываются ограничения по глубине и числу страниц.
- Извлечение контента. С каждой страницы извлекаются текст, заголовки, ссылки, телефоны, цены, мета-данные.
- Структурирование (AI-слой). Hermes сводит собранное в профиль: описание бизнеса, услуги, цены, контакты, карта страниц, офферы.
- Сохранение в память. Профиль и карта страниц сохраняются в БД и привязываются к customer_id. Фиксируется дата краулинга.
- Сводка менеджеру. Бот присылает краткую сводку: сколько страниц обойдено, какие услуги и цены найдены, какие контакты извлечены.

> 🤖 Бот Краулинг kasimotors.co.ke завершён. • Обойдено страниц: 18 • Найдены разделы: Каталог, Поддержанные авто, Рассрочка, Trade-in, Гарантия, Контакты, О нас • Услуги: продажа б/у авто, рассрочка, trade-in, проверка авто • Цены: седаны от $4000, внедорожники от $7000 (со страницы каталога) • Телефон: +254 712 345 678 · Instagram, Facebook найдены Профиль клиента обновлён. Готов использовать в кампаниях и объявлениях.

> Параметры и ограничения краулинга (уточнить на этапе внедрения) • Глубина и объём: задаётся максимальная глубина обхода и лимит страниц (например, до 50–100 страниц), чтобы не перегружать большие сайты. • Уважение к robots.txt: краулер учитывает robots.txt и не обходит запрещённые разделы; ставит разумные задержки между запросами. • Только один домен: обход ограничен доменом клиента; внешние ссылки (соцсети, маркетплейсы) фиксируются как ссылки, но не краулятся вглубь. • Динамические сайты: для сайтов на JS может потребоваться рендеринг страниц (headless-браузер) — закладывается опционально. • Стоимость и время: краулинг больших сайтов выполняется асинхронно, менеджер получает результат по готовности.

## 20.5 Обновление и повторный краулинг
Если сайт клиента изменился (новый сайт, новые услуги, новые цены), менеджер обновляет профиль одним из способов. Агент перед перезаписью памяти показывает изменения «было → станет» и сохраняет предыдущую версию профиля в истории.

| Способ обновления | Поведение системы |
|---|---|
| Прислать новый текст («Обновить инфу») | Менеджер отправляет обновлённую информацию; агент разбирает и обновляет соответствующие поля, остальные оставляет без изменений. |
| Сменить сайт | Менеджер присылает новый URL; агент обновляет поле «Сайт» и предлагает перекраулить новый адрес. |
| 🔄 Перекраулить полностью | Полный повторный обход сайта; профиль (услуги, цены, карта страниц) пересобирается заново. |
| Перекраулить только новое | Обход с поиском новых/изменённых страниц; в профиль добавляются изменения, существующие данные сохраняются. |

> 👤 Менеджер «У Kasi Motors обновился сайт, теперь kasimotors.com. Перекрауль всё.»

> 🤖 Бот Обновляю профиль клиента Kasi Motors: • Сайт: kasimotors.co.ke → kasimotors.com Запускаю полный повторный краулинг нового адреса. Пришлю сводку по готовности. ✅ Подтвердить    ❌ Отмена

## 20.6 Использование профиля в генерации
Профиль клиента — основной контекст для всех генеративных задач агента. Он используется совместно с ключевыми словами кампании и содержимым посадочной страницы (раздел 19) для максимально релевантной генерации.

| Где используется | Что берётся из профиля |
|---|---|
| Заголовки (15 RSA) | Бренд, услуги, УТП, гео, цены — для релевантных заголовков (раздел 19.5.2). |
| Описания (4 RSA) | Описание бизнеса, преимущества, офферы, цены — для описаний (раздел 19.5.3). |
| Sitelinks | Карта страниц сайта — главные и релевантные страницы как доп. ссылки (раздел 19.7.2). |
| Structured snippets | Категории услуг/товаров (например, типы авто) из профиля. |
| Callouts | Короткие УТП: гарантия, рассрочка, trade-in и т. п. |
| Телефон / Call | Контактный номер клиента из профиля. |
| Price / Promotion | Цены и акции клиента, если они известны. |
| Keyword research | Профиль и URL используются для генерации seed-слов и фильтрации релевантности (раздел 19.4.2). |
| Display path | Тематика бизнеса и страницы — для релевантных сегментов пути. |

> Принцип релевантности Сайты клиентов бывают большими, со множеством услуг. Агент тщательно собирает информацию и хранит контекст по клиенту, чтобы при генерации заголовков, описаний и ассетов выбирать именно те услуги, цены и преимущества, которые релевантны конкретной кампании и её ключевым словам, а не весь сайт сразу.

## 20.7 Хранение данных (дополнение к разделу 13)
Профиль клиента хранится в базе данных (PostgreSQL, см. раздел 13) и привязан к customer_id рекламного аккаунта. Рекомендуемые сущности:

| Сущность / таблица | Содержание |
|---|---|
| client_profile | customer_id, название, описание бизнеса, гео, язык, заметки, дата создания/обновления. |
| client_contacts | Телефоны, e-mail, адреса, ссылки на соцсети. |
| client_services | Услуги/товары: название, описание, цена (если есть), категория. |
| client_site_pages | Карта страниц после краулинга: URL, title, тип страницы, ключевые ссылки. |
| client_profile_history | История версий профиля (для отката и аудита изменений). |
| crawl_jobs | Журнал задач краулинга: домен, статус, число страниц, дата, ошибки. |

- Все изменения профиля фиксируются в audit log (кто, когда, что изменил) — в соответствии с разделом 12 основного ТЗ.
- Краулинг и хранение контента сайта выполняются с учётом политик и применимого законодательства; сохраняются только данные, необходимые для генерации рекламных материалов.

## 20.9 Критерии приёмки

> В меню бота есть пункт «Информация про клиентов»; за каждым рекламным аккаунтом (customer_id) закрепляется отдельный профиль клиента. Менеджер может отправить информацию о клиенте обычным текстом, и бот корректно разбирает и сохраняет её в память (описание, сайт, соцсети, услуги, цены, телефоны). Работает кнопка «Обновить инфу»: профиль можно дополнить или изменить; изменения показываются «было → станет», предыдущая версия сохраняется. По ссылке на сайт бот запускает краулинг, собирает основные страницы и ссылки, извлекает услуги, цены (если указаны) и контакты, и сохраняет структурированный профиль. Доступен повторный краулинг (полный и только новые страницы) при обновлении сайта клиента. Профиль клиента используется при генерации заголовков, описаний и ассетов, обеспечивая релевантность конкретной кампании и ключевым словам. Все изменения профиля и задачи краулинга фиксируются в audit log.
