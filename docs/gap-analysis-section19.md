# Gap-анализ: Спека §19 vs реализация `/newcampaign`
# Дата: 2026-07-30

## Сводка

Реализация покрывает **~85%** спеки. Ключевые гэпы ниже.

---

## GAP-1 (P0): Аккаунт мутации

| | Спека §19.2 | Реализация |
|---|---|---|
| **Где создаётся кампания** | На выбранном клиентском аккаунте | На `_active_read_account(chat_id)` — дефолт Draft `7753643025` |
| **Код** | — | `bot/main.py:4528-4531` (`_cc_begin`) |

**Деталь:** Метод `set_account()` (`bot/campaign_wizard/store.py:218-239`) **уже** переключает `customer_id` на выбранный клиентский. Вызывается в `cc_account_cb` (`bot/handlers/campaign_wizard.py:93`). Блокирует только `ensure_allowed()` в `_present_proposal` (`bot/main.py`), проверяющий `allowed_customer_ids` (`core/config.py`).

**Решение:** Добавить боевые аккаунты в `allowed_customer_ids` или добавить явный флаг `allow_campaign_creation` на аккаунт.

## GAP-2 (P1): Гео-радиус (proximity targeting)

| | Спека §19.3 | Реализация |
|---|---|---|
| **Гео** | Страна + **города + радиус (км)** — опционально | Только страны/города, радиус НЕ собирается в визарде |
| **Парсер** | — | `bot/main.py:3944` (`_parse_geo_proximity`) — **уже есть**, но не используется в визарде |
| **Схема мутации** | — | `agent/tools/schemas.py:458-463` (`SetGeoProximity`) — **уже есть** |
| **Извлечение из описания** | — | `agent/campaign_settings.py:47` — `geo_locations` извлекаются, но proximity — нет |

**Решение:** Дополнить `extract_campaign_settings` полем `geo_proximity`, подключить в сводку Этапа 1, добавить в `assemble_settings`.

## GAP-3 (P2): Image eligibility check

| | Спека §19.6 | Реализация |
|---|---|---|
| **Проверка доступности** | Проверять eligibility image assets для аккаунта | НЕ проверяется — этап изображений показывается всегда |
| **Документировано** | — | `docs/CAMPAIGN_WIZARD.md:178-179` — явно признано |

**Реальность:** Google Ads API не предоставляет метод проверки eligibility image assets. Доступность зависит от истории аккаунта, отсутствия нарушений политик. Единственный способ — попытаться создать и получить ошибку.

**Решение:** Добавить advisory-предупреждение на Этапе 4: «Image assets могут быть недоступны для этого аккаунта. Если неприменимы — ассет будет пропущен при создании». Плюс `assets_skipped` в результате.

## GAP-4 (P2): Location / Affiliate assets

| | Спека §19.7.1 | Реализация |
|---|---|---|
| **Location** | Адрес и карта (Google Business Profile) | `ads/extensions.py:386-387` — **config-gated**, требует AssetSet + place_id |
| **Affiliate** | Сеть магазинов-партнёров | `ads/extensions.py:388` — **удалён из API v24** (Google deprecation) |

**Решение:** Location — подключить через Place ID из профиля клиента (если есть). Affiliate — задокументировать как невозможный в v24.

## GAP-5 (P3): Кириллица в display path

| | Спека §19.5.1 | Реализация |
|---|---|---|
| **Подсчёт символов** | Кириллица = **2** символа | Кириллица = **1** code point |

**Вердикт:** Спека **ошибается**. Google Ads считает кириллицу за 1 code point. Реализация корректна (`adcopy/validate.py:22`, golden rule #4). Утверждение спеки §19.5.1 «для кириллицы символ считается как 2» — **ошибка документа**, не баг кода.
