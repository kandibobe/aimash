# Keyword research (`/keywords`, ТЗ §7/§13)

> **[legacy-референс]** Keyword Planner, фильтрация, кластеры, интенты, минус-слова, match type и экспорт — сохраняемый конвейер.
> `/keywords`, кнопки отбора и callback-состояние — legacy UX. В Hermes каждый шаг становится отдельным READ/PLAN-инструментом, а порядок выбирает агент
> (`SPEC.md` §3.3, §6.1).

Подбор ключевых слов с объёмом/конкуренцией + AI-кластеризация по интенту + выгрузка `.xlsx`.
**READ-ONLY, advisory** — ничего в аккаунте не меняется, confirm-гейт не нужен (как и отчёты).
Реализация: [`ads/keyword_plan.py`](../ads/keyword_plan.py) (идеи + метрики) и
[`keywords/cluster.py`](../keywords/cluster.py) (кластеризация); тесты —
[`tests/test_keyword_plan.py`](../tests/test_keyword_plan.py).

## Подбор идей — `generate_keyword_ideas`
Источник — **KeywordPlanIdeaService** (Google Ads API v25). Сиды:
- **ключи** (`seeds`) и/или **URL** — можно комбинировать (`keyword_and_url_seed`; только ключи →
  `keyword_seed`; только URL → `url_seed`);
- **язык**: `ru`=1031, `uk`=1036, `en`=1000 (по умолчанию `ru`);
- **гео**: по умолчанию Украина (`geoTargetConstants/2804`), переопределяемо;
- сеть — `GOOGLE_SEARCH`.

Замок аккаунта (`ensure_allowed`) — **до** любого запроса (golden rule #9). Лимит сервиса ~1 QPS →
серийно с экспоненциальным backoff (3 попытки только на rate-limit: `RESOURCE_EXHAUSTED`/`QUOTA`).

### Что считает КОД (не модель)
Из каждого ряда `keyword_idea_metrics` код вытаскивает: `avg_monthly_searches`, `competition`
(LOW/MEDIUM/HIGH), `competition_index` (0–100), ставки top-of-page и `average_cpc` (micros→валюту
делит **код**), а также **пик сезона** (`peak_month`, §7) — месяц максимума из ряда
`monthly_search_volumes`, напр. «дек 2025» (пусто, если ряда нет).

### Объём выборки
Тянем до `_FETCH_CEILING=500` идей (≈бюджет одного запроса), **сортируем весь пул по объёму** и
отдаём топ-`MAX_IDEAS=200`. Обрезка делается **после** сортировки (API отдаёт по релевантности —
иначе ёмкие ключи на дальних позициях терялись бы). Достижение потолка логируется.

> **Тест-аккаунт.** На `7753643025` объём/конкуренция приходят реально, а оценки ставок (CPC/bids)
> нулевые — ограничение тестовой среды, не баг.

## Кластеризация — `cluster_keywords`
LLM (роль `parsing`, дёшево) группирует ключи по интенту: `транзакционный | информационный |
брендовый | навигационный`. Модели уходит **только список ключей** — метрики к ней не попадают.
Защита от мусора:
- оставляем лишь **реально присланные** ключи (по `casefold`, с возвратом исходного написания) —
  модель не может выдумать новых;
- дедуп между группами; неразложенные ключи → группа «Прочее»;
- вход усекается до `MAX_CLUSTER_INPUT=200`, остаток → «Прочее (сверх лимита)» (без тихой потери);
- сбой/пустой ответ → **fallback** «Все ключи» (фича не падает).

## Выгрузка
Результат экспортируется в `.xlsx` (см. [`keywords/export.py`](../keywords/export.py)) и присылается
вложением; краткая сводка — в чат.

Близко по духу — отчёты ([REPORTS.md](REPORTS.md)): тоже read-only и метрики считает код.
